**Added**

- **Linux desktop app (BETA).** freemkv now ships a native GTK4 + libadwaita
  desktop app on Linux, alongside the existing macOS (AppKit) and Windows
  shells — the same product on all three, driven by the same core. Distributed
  as a Flatpak on Flathub (submission in progress, app ID
  `org.freemkv.FreeMKV`) and as a portable AppImage from the packaging
  workflow. The window, hamburger menu, notifications and settings are wired
  up; the main-content panels (source picker, title list, output, progress
  and log) are being ported one at a time from the macOS shell. The Linux
  CLI is production-quality and remains the recommended path for anyone
  who needs to rip today.
- **Rip-finished desktop notification.** When a rip completes, the app fires
  a native notification on the OS notification centre — toast on Windows,
  Notification Center on macOS, XDG Desktop Portal + in-window AdwToast on
  Linux. Off from Settings if you don't want it (default: on).

**Under the hood**

- The menu bar on macOS and Windows is now one shared decision instead of
  two hand-built copies — adding or renaming a menu row is a one-line edit
  that reaches every shell. Not a visible change; it's the mechanism that
  makes "one bug fix, every OS" a promise rather than a hope. A cross-shell
  contract test in the repo pins that every user-driveable command appears
  in the shared layout.

_This release aligns all components to 1.7.6._
